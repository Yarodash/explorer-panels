# Explorer Panels — проект устройства

Дата: 2026-11-15. Статус: на согласовании.

## Зачем

В окне настоящего Проводника Windows 11, в правом нижнем углу области файлов, висит панель управления
проектом: статусы серверов, кнопки «запустить», «открыть сайт», «выключить», «логи» и любые другие элементы.
Панель есть только в тех папках, где она описана, и ощущается частью Проводника.

Главный сценарий, под который всё проектируется:

1. Программа установлена и всегда работает в системе (значок в трее, автозапуск).
2. В любом проекте владелец говорит Claude: «добавь кнопок управления текущим проектом» и даёт ссылку на
   репозиторий (или у Claude установлен навык из репозитория).
3. Claude читает короткий раздел для агентов, смотрит проект, пишет один файл `.explorer_components/panel.json`,
   выполняет `explorer-panel trust .` и `explorer-panel check .`.
4. Панель сразу появляется в Проводнике. Владелец ничего не настраивает руками.

Поэтому главный критерий решений — **насколько легко и безошибочно панель напишет Claude**, у которого есть
только ссылка на репозиторий.

## Цели

1. Панель ощущается частью Проводника: держится на месте при перемещении и изменении размера окна, сворачивается
   и разворачивается вместе с ним, видна только в активной вкладке нужной папки, не всплывает поверх чужих окон,
   не забирает фокус.
2. Папка подключается одним файлом. Панель появляется сама, как только файл стал валидным, и обновляется при
   каждом его изменении, без перезапусков.
3. Простой случай описывается декларативно, без кода и без сборки. Ошибки описания видны агенту сразу, одной
   командой, с номером строки.
4. Для сложного вида доступен полный набор компонентов shadcn/ui.
5. Серверы запускаются и останавливаются по-настоящему, работают невидимо, статус всегда соответствует
   действительности.
6. Данные панели обновляются в обе стороны: панель сама опрашивает источники, а внешняя программа может
   мгновенно прислать новое значение.
7. Программа ставится одной командой, стартует вместе с системой, в простое почти ничего не потребляет.
8. Репозиторий готов к публикации на GitHub: по нему может собрать и поставить программу другой человек,
   а агент — добавить панель.

## Не цели

- Другие файловые менеджеры, другие ОС, Windows 10.
- Внедрение кода в процесс Проводника. Это запасной путь, только если приклеенное окно будет отвергнуто по
  ощущениям.
- Каталог готовых панелей, синхронизация между машинами, удалённое управление.
- Автообновление программы. Обновление — повторный запуск установки.

## Чего нельзя допустить

- Проводник падает, зависает или заметно тормозит из-за программы.
- Команды из папки выполняются до того, как владелец (или его агент) разрешил панель этой папки.
- Панель перехватывает клики или клавиши, предназначенные Проводнику, либо всплывает поверх других программ.
- Статус показывает «работает», когда сервер лежит, или наоборот.
- Чтобы добавить панель, агенту нужно что-то собирать, ставить зависимости в проект или угадывать формат.

## Ограничения

- Windows 11, Проводник со вкладками. Официального способа добавить свою кнопку в окно Проводника нет.
- Программа: C# на .NET 10. Вид панели: React + shadcn/ui внутри WebView2 (движок уже есть в Windows 11).
- Автоматические проверки окон идут на отдельном виртуальном рабочем столе «Claude tests», живой экран не
  снимается.

## Рассмотренные подходы

### Как встроить панель в Проводник

| Подход | Плюсы | Минусы |
|---|---|---|
| **Окно-спутник**: отдельное окно, владелец которого — окно Проводника (выбран) | Работает с браузерным движком и shadcn; не ломается от обновлений Windows; не может уронить Проводник | При быстром перетаскивании окна панель догоняет его с задержкой в кадр-два |
| Дочернее окно внутри окна Проводника | Нет задержки при перетаскивании | Работает только с родными элементами Windows, shadcn в нём не получить; зависший процесс панели подвесил бы Проводник |
| Внедрение кода в процесс Проводника | Панель буквально внутри | C++, без React; любое обновление Windows может сломать или уронить Проводник |

Выбрано окно-спутник: только оно даёт shadcn. Прототип подтвердил, что оно работает.

### Как описывать панель в папке

| Подход | Плюсы | Минусы |
|---|---|---|
| Только JSON | Просто, проверяется схемой | Для каждого компонента shadcn нужно придумать своё описание; сложная логика не выражается |
| Только React-файл | Полная свобода | Даже для трёх кнопок агент пишет код; ошибки видны только при сборке |
| **JSON для данных и простого вида + необязательный `panel.tsx` для своего вида** (выбран) | Простой случай — один маленький файл без кода; сложный — обычный React, который Claude пишет уверенно | Два способа задать вид вместо одного |

Выбран третий: в девяти случаях из десяти агент пишет только JSON, который проверяется до запуска.

## Устройство

### Части программы

1. **Программа-хозяин** — один исполняемый файл `explorer-panel.exe`. Без аргументов работает как фоновая
   программа со значком в трее; с аргументами — как команда для агента и скриптов.
   - **Слежение за Проводником.** Знает, какие окна открыты, какая папка в активной вкладке каждого и где
     область файлов.
   - **Поиск панели.** Для папки активной вкладки ищет ближайшую вверх по дереву подпапку
     `.explorer_components` с валидным `panel.json` (как ищут `.git`). Следит за файлами и перечитывает их при
     изменении.
   - **Окно панели** — по одному на окно Проводника, в котором есть панель.
   - **Серверы** — запуск, остановка, проверка «жив ли», статусы, логи.
   - **Действия** — разовые команды и открытие адресов.
   - **Значения** — именованные данные проекта: статусы серверов, результаты обработчиков, присланное снаружи,
     сохранённые переключатели. Страница подписана на них и обновляется сразу.
   - **Местный интерфейс для команд** — принимает запросы от команды `explorer-panel` и от внешних программ.
2. **Страница панели** — React + shadcn/ui, собирается один раз вместе с программой. Рисует стандартную панель
   по `panel.json` либо свой вид из `panel.tsx`.

### Папка проекта

```
my-project/
  .explorer_components/
    panel.json        обязательно: серверы, действия, значения, виджеты
    panel.tsx         необязательно: свой вид на React + shadcn
    handlers/         необязательно: скрипты-обработчики на любом языке
    logs/             создаёт программа: вывод серверов и действий
    .gitignore        создаёт программа, если его нет: исключает logs/
```

### `panel.json`

```json
{
  "$schema": "https://raw.githubusercontent.com/<владелец>/explorer-panels/main/schema/panel.schema.json",
  "version": 1,
  "services": {
    "api": { "run": "python -m uvicorn main:app --port 8000", "cwd": "backend", "health": "http://localhost:8000/api/hello" },
    "web": { "run": "npm run dev -- --port 5173 --strictPort", "cwd": "frontend", "health": "http://localhost:5173" }
  },
  "actions": {
    "site":  { "open": "http://localhost:5173", "needs": ["api", "web"] },
    "tests": { "run": "pytest -q", "cwd": "backend" }
  },
  "values": {
    "branch": { "run": "git branch --show-current", "every": 15 }
  },
  "widgets": [
    { "type": "text", "icon": "git-branch", "text": "{branch}" },
    { "type": "status", "service": "api" },
    { "type": "status", "service": "web" },
    { "type": "button", "icon": "play", "tooltip": "Запустить", "do": "start" },
    { "type": "button", "icon": "globe", "tooltip": "Открыть сайт", "do": "site" },
    { "type": "button", "icon": "square", "tooltip": "Выключить", "do": "stop" },
    { "type": "button", "icon": "file-text", "tooltip": "Логи", "do": "logs" }
  ]
}
```

Правила формата:

- **Одно слово `run`** везде, где выполняется команда: в серверах, действиях, значениях. `env` — переменные
  окружения.
- **Как выполняются команды.** Через `cmd.exe /c`, то есть так же, как если набрать их в обычной командной
  строке Windows. Рабочая папка по умолчанию — корень проекта (папка, в которой лежит `.explorer_components`),
  одинаково для серверов, действий и обработчиков. `cwd` задаёт другую папку относительно корня проекта.
- **`services`** — долгоживущие процессы. `health` — адрес (сервер жив, если отвечает) либо `{ "run": "..." }`
  (жив, если команда завершилась с кодом 0). Без `health` сервер считается работающим, пока жив его процесс.
  Необязательное `stop` — команда остановки (например, `docker compose down`); без неё сервер останавливается
  завершением его процессов.
- **`actions`** — разовые действия: `run` (команда) или `open` (адрес, файл, папка). `needs` — серверы,
  которые нужно поднять и дождаться перед действием.
- **Встроенные действия:** `start`, `stop`, `restart` (все серверы), `start:имя`, `stop:имя`, `restart:имя`,
  `logs`.
- **`values`** — именованные значения, см. ниже.
- **`widgets`** — что показать, слева направо. Если `widgets` нет, панель строится сама: статус каждого
  сервера, кнопки запуска и остановки, кнопка на каждое действие, «логи». То есть минимальный файл — это
  только `services`.
- **`scope`** — `"tree"` (по умолчанию: панель видна в корне проекта и во всех его подпапках) или `"folder"`
  (только в самой папке).
- **Иконки** — имена из набора lucide (`play`, `globe`, `git-branch`).
- **Подстановки** `{имя}` в `text`, `tooltip`, `run` и `open` заменяются текущим значением. В `text` и
  `tooltip` — как есть. В `open` значение кодируется как часть адреса. В `run` подставляется только значение
  из безопасных символов (буквы, цифры и `. _ - / : @ +`); иначе команда не выполняется, а в лог пишется
  причина. Так название ветки или текст, пришедший снаружи, не может превратиться в постороннюю команду.

### Стандартные виджеты

Каждый — готовый компонент shadcn. Набор намеренно небольшой и однородный; всё, чего в нём нет, делается в
`panel.tsx`.

| `type` | Что это | Главные поля |
|---|---|---|
| `status` | точка статуса с подписью | `service` или `value` |
| `button` | квадратная кнопка с иконкой и подсказкой | `icon`, `tooltip`, `do` |
| `text` | текст, обычно со значением | `text`, `icon` |
| `toggle` | тумблер | `value`, `label`, `on`, `off` (действия) |
| `select` | выбор из вариантов | `value`, `options`, `do` |
| `progress` | полоса 0–100 | `value` |
| `menu` | кнопка с выпадающим списком | `icon`, `items: [{ label, do }]` |
| `clock` | текущее время | — |
| `stopwatch` | секундомер | — |
| `calendar` | кнопка с датой и всплывающим календарём | `do` (получает `{date}`) |
| `separator` | разделитель | — |
| `slot` | виджеты, которые вернул обработчик | `value` |

Статус имеет четыре состояния: `stopped` (серый), `starting` (жёлтый, мигает), `running` (зелёный),
`failed` (красный).

### Значения, обработчики и обновление снаружи

Значение — именованная единица данных проекта. Источников три, и это покрывает «в обе стороны»:

1. **Обработчик.** `{ "run": "python .explorer_components/handlers/commits.py", "every": 60 }` — команда
   запускается раз в `every` секунд. Её вывод:
   - обычный текст становится значением;
   - JSON-объект с ключами `value`, `ttl`, `widgets` — «конверт»: `value` становится значением, `ttl` задаёт,
     через сколько секунд запустить снова, `widgets` показывается виджетом `slot`. Так скрипт сам отдаёт
     компоненты и срок их жизни.
2. **Присланное снаружи.** Любая программа может мгновенно установить значение:
   `explorer-panel set deploy=running` или запросом к местному интерфейсу. Панель обновляется сразу.
3. **Сохранённое.** Значение без `run` хранит сама программа (состояние тумблера, выбранный вариант). Оно
   переживает перезапуск.

Статус сервера — тоже значение. Виджет `status` можно привязать не к серверу, а к значению, которое
присылает сама программа проекта.

### Свой вид: `panel.tsx`

Если файл есть, он рисует панель вместо стандартных виджетов. Это обычный React:

```tsx
import { Button } from "@/components/ui/button"
import { Panel, useService, useValue, run } from "explorer-panel"

export default function MyPanel() {
  const api = useService("api")
  const [branch] = useValue("branch")
  return (
    <Panel>
      <span>{branch}</span>
      <Button onClick={() => run("tests")}>Тесты</Button>
    </Panel>
  )
}
```

- Доступны все компоненты shadcn, иконки lucide и модуль `explorer-panel` (серверы, значения, действия).
- Программа сама собирает файл при сохранении. В проект ничего ставить не нужно.
- Данные и команды по-прежнему описаны в `panel.json`; `panel.tsx` отвечает только за вид.

### Серверы

- Запускаются невидимо. Вывод пишется в `.explorer_components/logs/services.log` с пометкой `[имя]`; файл
  обрезается при достижении разумного размера. Действие `logs` открывает его в Блокноте.
- Статусы: процесс запущен, но не отвечает — `starting`; отвечает — `running`; завершился сам, хотя его не
  останавливали — `failed`; остановлен — `stopped`.
- **Чей это сервер.** Сервер считается сервером проекта в двух случаях: его запустила панель (программа
  помнит номер процесса и время запуска) либо процесс, который слушает порт из `health`, работает из папки
  внутри проекта. Второе покрывает сервер, запущенный руками из терминала: он показывается как `running`,
  и «выключить» его останавливает.
- **Чужой процесс на порту.** Если порт из `health` занят программой не из этого проекта (например, другим
  проектом на том же порту 5173), статус — `failed` с подсказкой «порт занят другой программой: имя, номер
  процесса». Такой процесс панель никогда не завершает, а «запустить» сообщает о занятом порте.
- **Остановка.** Если задано `stop` — выполняется эта команда. Иначе завершается всё дерево процессов
  сервера. Процессы, не принадлежащие проекту, не трогаются.
- **Команды-запускалки.** Если `run` завершился с кодом 0 (например, `docker compose up -d`), сервер не
  считается упавшим: его статус дальше определяется только по `health`, поэтому для таких серверов `health`
  обязателен. Ненулевой код — `failed`.
- Серверы продолжают работать, если программа-хозяин закрылась или перезапустилась; после запуска она находит
  их снова.

### Доверие

Панель может выполнять команды, поэтому папке нужно разрешение.

- Пока папка не разрешена, команды не выполняются и `panel.tsx` не загружается. Вместо панели показывается
  маленькая плашка «Разрешить панель этой папки?» с кнопками «Разрешить» и «Нет».
- `explorer-panel trust <папка>` делает то же самое из командной строки. Агент, который добавляет панель,
  выполняет эту команду сам, и владельцу не приходится ничего нажимать.
- Разрешение хранится по пути корня проекта и не спрашивается заново при изменении файлов. Список
  разрешённых и запрещённых папок доступен из меню в трее.

### Команда `explorer-panel`

Тот же исполняемый файл с аргументами. Папка по умолчанию — текущая, корень проекта ищется вверх по дереву.

| Команда | Что делает |
|---|---|
| `check` | Проверяет `panel.json` и `panel.tsx`: по строке на проблему, с файлом и номером строки, с подсказкой («неизвестная иконка `playy`, возможно `play`»). Код возврата 1 при ошибках. Сообщает, загружена ли панель и разрешена ли папка. Работает и без запущенной программы. Для `panel.tsx` проверяются синтаксис, импорты и наличие компонента по умолчанию; проверки типов нет. Если программа запущена, дополнительно сообщается последняя ошибка, возникшая при показе панели. |
| `trust`, `untrust` | Разрешить или запретить панель папки. |
| `status` | Серверы и значения проекта в виде JSON. |
| `start`, `stop`, `restart` | Управление серверами. |
| `do <действие>` | Выполнить действие. |
| `set имя=значение` | Мгновенно установить значение. |
| `logs` | Путь к логу и его последние строки. |
| `screenshot -o файл.png` | Снимок панели, чтобы агент увидел результат. |
| `install`, `uninstall` | Автозапуск и добавление в PATH. |

Местный интерфейс для этих команд и внешних программ слушает только на этом компьютере и отклоняет запросы,
пришедшие из веб-страниц в браузере.

### Поведение в Проводнике

Подтверждено прототипом, должно сохраниться:

- Панель прижата к правому нижнему углу области файлов, не залезает на дерево папок и строку состояния.
- Видна только в активной вкладке папки с панелью. При переходе в папку без панели исчезает.
- Следует за окном при перемещении и изменении размера; прячется при сворачивании; переезжает вместе с окном
  на другой рабочий стол; в стопке окон лежит сразу над своим Проводником.
- Не забирает фокус. Клик по панели выводит её Проводник на передний план.
- Клики мимо видимых частей панели проходят в Проводник. Всплывающие части (подсказки, календарь, меню)
  тоже принимают клики.
- Если панель не помещается, крайние слева виджеты прячутся целиком и появляется кнопка «расширить окно».
  Она увеличивает окно Проводника ровно на недостающую ширину, не выходя за экран.
- Панель можно свернуть до статусов и основных кнопок; состояние запоминается для проекта.
- Курсор-рука на всём нажимаемом, заметная подсветка при наведении, тёмная или светлая тема по системе.
- Несколько окон Проводника с одним проектом показывают одинаковое состояние.
- Перезапуск Проводника программа переживает.

Ввод с клавиатуры в панели (поля ввода в своём `panel.tsx`): окно панели получает фокус только после клика в
поле ввода и возвращает его Проводнику, когда ввод закончен.

### Установка и постоянная работа

- `scripts/install.ps1` собирает программу, кладёт её в папку пользователя, добавляет в PATH, включает
  автозапуск при входе в систему и запускает. Повторный запуск обновляет программу; работающие серверы при
  этом не останавливаются.
- Один экземпляр программы на пользователя. Значок в трее: проекты с работающими серверами, разрешённые
  папки, пауза, выход.
- В простое (ни одной видимой панели) программа занимает меньше 100 МБ и не нагружает процессор. Браузерный
  движок создаётся, когда панель нужна, и освобождается, когда панели давно не видно.

Всё, что нужно агенту, чтобы добавить панель по одной ссылке:

- **README начинается с рецепта** «Добавить панель в проект»: что создать, какие две команды выполнить,

## Что выяснил прототип

Это проверенные решения, их не нужно искать заново:

- Окно панели — окно верхнего уровня с владельцем-Проводником и стилями «не активировать» и «служебное окно».
  Новое окно Windows кладёт на верх стопки, поэтому его нужно явно ставить сразу над владельцем.
- Прозрачность: окно без собственной поверхности (`WS_EX_NOREDIRECTIONBITMAP`) + WebView2 в оконном режиме с
  прозрачным фоном. Композитный вариант WebView2 для WPF прозрачность не умеет.
- WinForms сбрасывает форме владельца — его нужно выставлять заново. Он же добавляет стиль «окно приложения»
  (`WS_EX_APPWINDOW`), из-за которого панель видна отдельным окном в панели задач и в Alt+Tab, — стиль нужно
  снимать.
- Клики мимо панели: страница каждый кадр сообщает прямоугольники видимых частей, окно обрезается по ним.
- Привязка — к области файлов (`SHELLDLL_DefView`), а не к рамке окна.
- Активная вкладка определяется сравнением окна вкладки с верхним окном вкладок Проводника.
- Проверка `localhost` на Windows зависает на втором семействе адресов — нужно пробовать оба сразу.
- Снимать окно панели с настоящей прозрачностью можно через Windows.Graphics.Capture, в том числе на другом
  рабочем столе; `PrintWindow` для этого не годится.
- Цена: браузерный движок занимает около 450 МБ на две открытые панели, сама программа — около 120 МБ.

## Проверки

- **Модульные (C#):** разбор и проверка `panel.json`, подстановки, переходы статусов, список разрешённых папок.
- **Страница (React):** стандартные виджеты по JSON, скрытие виджетов при нехватке места.
- **Сквозные** на рабочем столе «Claude tests»: появление и исчезновение панели, следование за окном,
  вкладки, порядок окон, автоподхват файла, область кликов, запуск, остановка и падение сервера, команда
  `check`.
- **Руками владельца** (настоящей мышью это не автоматизируется): подсветка при наведении, проход кликов
  мимо панели, плавность при перетаскивании, клавиатура в полях ввода.

## Этапы

1. **Основа.** Репозиторий, программа-хозяин, окно панели, стандартные виджеты по `panel.json`, автоподхват,
   серверы и логи. Результат: всё, что умеет прототип, но по описанию из файла.
2. **Команды и данные.** Команда `explorer-panel` (`check`, `trust`, `status`, `do`, `set`), местный интерфейс,
   плашка доверия, значения, обработчики, обновление снаружи.
3. **Постоянная работа.** Установка, автозапуск, трей, один экземпляр, экономия в простое.
4. **Для агентов.** README-рецепт, справочник, схема, примеры, навык.
5. **Свой вид.** `panel.tsx`, клавиатура в полях ввода, команда `screenshot`.
6. **GitHub.** Публикация репозитория и готовой сборки.

Главный сценарий работает после этапов 1–4.

## Решения, принятые за владельца

Их стоит проверить при чтении:

1. Формат: `panel.json` плюс необязательный `panel.tsx`; команда запуска везде называется `run` (в прототипе
   было `start`).
2. Панель видна в корне проекта и во всех его подпапках.
3. Новой папке нужно разрешение: один клик владельца либо команда `trust`, которую выполняет агент.
4. Серверы продолжают работать, когда программа в трее закрыта или обновляется.
5. Остаётся окно-спутник с небольшим отставанием при перетаскивании; цена — несколько сотен мегабайт памяти,
   пока панели видны.
6. Свой вид на React делается последним этапом; до него доступны стандартные виджеты.
7. Название — Explorer Panels, команда `explorer-panel`, подпапка `.explorer_components`; документация
   репозитория на английском.
8. Имя и видимость репозитория на GitHub владелец называет в момент публикации.

Добавлено после чтения документа независимым проверяющим:

9. «Выключить» останавливает только серверы этого проекта: запущенные панелью или работающие из папки
   проекта. Чужая программа на том же порту показывается как проблема и никогда не завершается. В прототипе
   панель завершала любой процесс на порту — это небезопасно при двух проектах на одном порту.
10. У сервера есть необязательная команда `stop`, а команда-запускалка, завершившаяся успешно, не считается
    падением. Без этого не работал бы пример с Docker Compose.
11. Команды выполняются через `cmd.exe /c` из корня проекта; значения подставляются в команды только если
    состоят из безопасных символов.
12. `check` для `panel.tsx` ловит ошибки синтаксиса и импортов, но не ошибки типов; ошибки показа панели
    видны, когда программа запущена.
