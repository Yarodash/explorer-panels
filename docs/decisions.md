# Decisions made along the way

Every decision taken on the owner's behalf while building Explorer Panels, in the order it was made:
what was decided — why — what it costs if it was wrong. Copied from the work ledger.

- work directly on `main` — brand-new repository, single owner, the owner asked to build and push without reviewing — cost if wrong: no feature branch to discard; history can still be reset before the first push.
- no per-task check-ins and no plan review by the owner ("не буду смотреть, собирай") — cost if wrong: decisions surface only in the final message.
- Host, Cli and Tests target `net10.0-windows` instead of `net10.0-windows10.0.19041.0` — the WinRT projection was only needed by the WPF composition control the prototype abandoned — cost if wrong: retarget one line per project.
- `PanelState` gained `problems: string[]` and `slots: Record<string, Widget[]>` beyond the plan's interface — the spec requires showing that a newer panel.json is broken and rendering handler-returned widgets; Task 7's `Project.BuildState` must emit both — cost if wrong: two unused fields.
- widgets live in three files by kind (`basic`, `controls`, `time`) plus the registry, not one file per type — each file stays small and widgets of a kind share helpers — cost if wrong: none for behaviour.
- fit hides widgets with CSS and remembers their last measured width instead of rendering a second hidden copy — a duplicate copy doubled every widget in the DOM and its timers — cost if wrong: a stale width after a config reload until the widget is shown once.
- added page message `activate` (sent on any pointer press) so a click on the panel brings its Explorer forward, as the spec's behaviour list requires — the prototype did this inside WPF, the WebView2 page needs a message — cost if wrong: Windows may refuse the foreground change; the click itself still works.
- added debug-only env switches `EXPLORER_PANEL_ONLY=<hwnd>` (limit the host to one Explorer window) and created `tests/e2e/lib.ps1` now instead of in Task 11 — the Task 6 check itself needs them and a test host must never touch the owner's windows — cost if wrong: none; both are inert without the variables.
- command output is decoded per line as strict UTF-8 with a fallback to the console (OEM) code page, and the `chcp 65001` prefix idea was dropped — tests showed cmd's own output stays in the OEM code page inside a windowless console — cost if wrong: a non-UTF-8, non-OEM tool would show garbled log lines.
- port ownership uses only the listening process's own working directory (plus descent from a panel-started process), not its parents' — a terminal opened in project A may have started project B's server — cost if wrong: a project server whose listener runs from outside the project folder is reported as foreign and is never killed (the safe direction).
- services that define `stop` skip port-ownership checks and are judged by `health` only — Docker publishes ports through its own proxy process, which would otherwise look foreign — cost if wrong: such a service can show running when another program answers its health URL.
- `ProjectTests` use real `python -m http.server` processes — the status rules are only meaningful against real ports and process trees — cost if wrong: the suite needs Python on the machine.
- added `PanelLoader.ValidWidgets` (core) to filter handler-returned widgets, and `StateFile`/`IShell` helpers in `Storage.cs` — required by slot widgets and by testability; not named in the plan — cost if wrong: none.
- Task 9 (single instance, tray, autostart, install) is executed before Task 8 (local API and CLI) — the owner asked why a working panel disappeared; installing first gives it back sooner — cost if wrong: none, the tasks do not depend on each other (the CLI gets `install`/`uninstall`/`version` now and the remaining commands in Task 8).
- the repository's own `.explorer_components/panel.json` (build, tests, install, example, logs) was added here instead of Task 10 — after the demo site moved to examples/ the owner's open folder had no panel — cost if wrong: none.
- pre-trusted `D:\explorer_buttons` and `examples\fastapi-react` in the owner's trust file — the owner asked for everything to work without their involvement, and the CLI `trust` command does not exist until Task 8 — cost if wrong: two folders of the owner's own repository are trusted without a click; revocable from the tray menu.
- `CheckCommand.Run(folder, output, trust, hostStatus)` takes the trust store and the host's status instead of a `HostClient` — keeps the command testable without HTTP and without the owner's real trust file — cost if wrong: none.
- `trust`/`untrust` write the trust file directly and need no running host (the host re-reads the file); `untrust` forgets the decision rather than blocking — an agent adds a panel before or after the host starts; "forget" is the reversible reading — cost if wrong: a folder cannot be blocked from the CLI, only from the panel's "No" button.
- added a fifth example `examples/git-info` (values from commands plus a handler script returning widgets and ttl) and used the same handler in the repository's own panel — the owner said they liked the git panel, and it is the one example that shows handlers — cost if wrong: one extra example.
- `$schema` is not put into examples and the README — the repository is private, so the raw schema URL would not resolve — cost if wrong: no editor completion until the key is added by hand.
- the debug restriction became `EXPLORER_PANEL_ONLY_UNDER=<folder>` (was a window handle) — lets the test host start before the Explorer window exists, which is the scenario "host finds a window opened later" — cost if wrong: none outside tests.
- an actual restart of explorer.exe (Review Focus 5) is not automated — killing Explorer would take down the owner's taskbar and windows; the automated scenario covers "window opened after the host started", the restart itself is on tests/e2e/manual-checklist.md — cost if wrong: a regression in recovery after an Explorer crash would be caught only by hand.
- the e2e run stops the installed host for its duration and restarts it — two hosts would both glue a panel to the test window — cost if wrong: the owner's panels vanish for about a minute per run.
- custom `panel.tsx` views, keyboard focus for text inputs and the `screenshot` command are NOT built in this run — the owner asked why the work was taking so long once a panel already worked, and their stated scenario (Claude adds control buttons to a project by writing panel.json) is fully served by Tasks 1-11; the standard widgets are already shadcn components — cost if wrong: the "full shadcn set" wish is unmet until Task 12 is done as a follow-up; the design marks it as the last stage and nothing in the shipped format has to change for it.
- the page no longer asks for focus to be returned to Explorer on pointerdown (`activate`); it sends `release` once the press is over and no menu, listbox or dialog is open, and the host returns focus only if the panel itself is the foreground window — Radix menus close on window blur, and returning focus mid-press blurred the page; the old handler also took the foreground away from another program during a test — cost if wrong: clicking a panel button while another program is in front no longer brings Explorer forward (the spec's behaviour list said it would).
- Task 12's custom panel.tsx views and keyboard input are dropped for good — the owner said the existing components are enough ("те что щас есть уже достаточно"); the screenshot command from the same task was built — cost if wrong: none, both can be added later.
- Claude buttons sit at the right end of a project's panel as a pinned item, stand alone in folders without panel.json, are shown next to the trust question too, and are absent on special pages (This PC, Home) — the owner asked for them "in all folders" — cost if wrong: placement is one component.
- Claude buttons are on by default and have their own check item in the tray menu; turning panels off hides them too — the owner asked for the buttons and for a tray switch — cost if wrong: one default in HostSettings.
- Claude opens through `cmd.exe /s /k "claude"` started by the Windows shell with the folder as working directory, not through wt.exe — works with any default terminal and keeps the folder name off the command line — cost if wrong: the owner may prefer PowerShell or a specific Windows Terminal profile (one line in Claude.cs).
- with Claude buttons on, a panel window exists for every folder window, so the browser engine stays loaded — unavoidable for buttons in every folder; the tray switch turns it off — cost if wrong: a few hundred MB of memory while Explorer is open.
- the Claude icon is taken from the simple-icons package (CC0 data) and the README says Claude is Anthropic's trademark — the owner asked for the Claude icon — cost if wrong: the icon is one import.
- the host replaces its whole environment with the sign-in environment (CreateEnvironmentBlock) and keeps only EXPLORER_PANEL_* — found by the owner: Claude opened by a button reported an inherited CLAUDE_CODE_CHILD_SESSION marker; stripping only CLAUDE* variables would also drop the owner's persistent settings and leave Git Bash's PATH additions — cost if wrong: a variable set only in the launching terminal no longer reaches services.
- a running service removed from panel.json is stopped — the panel started it and nothing else could stop it afterwards — cost if wrong: renaming a running service restarts nothing and stops the old process; the owner presses Start again.
- a value in a path `open` must stay inside the project folder, and values in addresses of any scheme are encoded — a pushed value must not open an arbitrary file or address — cost if wrong: a panel that legitimately opens files outside the project through a value stops working (write the path without a value).
- a value starting with - or / is refused only where it starts an argument — elsewhere it cannot become an option — cost if wrong: a rare legitimate value (a path like /api as a separate argument) is refused.
- literal braces are written doubled ({{ and }}) — the common convention; needed for commands like git rev-list @{u} — cost if wrong: none for existing files (doubled braces had no meaning before).
- the state-file race could not be reproduced by a test (five attempts, two shapes); the API was changed so that the state can only be read and changed under one lock — cost if wrong: none.
- disk lookups for Explorer folders moved to a background probe; the window thread uses the last known answer — cost if wrong: a panel appears a few milliseconds later than before.
- the ready-made build is a self-contained win-x64 zip (48 MB), unsigned, published as GitHub release v0.2.0 with version 0.2.0 — "Готовая сборка на GitHub" was on the owner's list and the owner said to finish without questions — cost if wrong: the release can be deleted; SmartScreen may warn about unsigned files.
- no LICENSE file was added — choosing a licence is the owner's decision — cost if wrong: the public repository stays formally "all rights reserved" until the owner decides.
- "$schema" was added to the examples and the repository's own panel — reverses the Task 10 ruling because the repository is public now — cost if wrong: none.
- PowerShell scripts got a byte-order mark — install.ps1 from the release zip runs under Windows PowerShell 5.1, which reads BOM-less files in the ANSI code page — cost if wrong: none.
